| 2026-10-19 | Require one client order ID from risk approval through broker submission and block automation until open-order reconciliation succeeds | Generate a new ID at submission / start automation optimistically | Prevent duplicate orders after ambiguous submissions or restarts; fail closed on missing reconciliation |
| 2026-10-19 | Legacy Alpaca order paths require an explicit caller-supplied risk gate and default to denial | Preserve unguarded legacy submission for compatibility | Legacy V1 loops do not own the modern risk engine; default denial prevents uncontrolled paper execution |
| 2026-10-20 | Host split: FastAPI backend on Railway, static dashboard on Cloudflare Pages; backend never deployed to Workers | Move backend to Cloudflare Workers | Backend needs native wheels (psycopg2-binary, ccxt, SB3) and a long-lived process; Workers runtime is incompatible. Only the vanilla-JS/CSS frontend ships to Pages |
| 2026-10-20 | `REQUIRE_DURABLE_STORE` env flag makes startup fail when `DATABASE_URL` is missing/unreachable (enabled by default in the production image - corrected 2026-10-26, previously and wrongly attributed to `railway.toml`) | Always require a DB / always allow the in-memory fallback | Production order/signal state must never silently live in ephemeral memory; the flag keeps local development (no DB) working |
| 2026-10-26 | Correction: safety env vars are baked into `Dockerfile.trader` (`REQUIRE_DURABLE_STORE=true`, paper-only flags), not `railway.toml` | Keep an unvalidated `[deploy.environment]` table / rely on dashboard-only defaults | Railway's config-as-code schema has no environment/variables key, so the previous table was silently ignored and `REQUIRE_DURABLE_STORE` was never actually set on Railway |
| 2026-10-26 | `railway.toml` stays the single deploy config (no parallel `railway.json`) and pins `builder = "DOCKERFILE"` + `dockerfilePath = "Dockerfile.trader"` | Add a second `railway.json` / rely on Railpack auto-detection | Two config files can diverge and Railway does not auto-detect non-standard Dockerfile names; explicit builder prevents a Railpack fallback for new services. Config-as-code itself is deprecated upstream (works until 2026-12-01) - migration to Infrastructure as Code is a follow-up, not part of this fix |
| 2026-10-26 | `trader/tests/test_deploy_config.py` makes the deploy config part of CI | Manual checklist only | The missing-Dockerfile deploy failed in production; the test fails fast when the referenced Dockerfile is absent, the restart policy is invalid, or paper-only/durable-store ENV values disappear |
| 2026-10-20 | Frontend API origin is injected at build time into `dist/config.js` by `scripts/build_frontend.js` (reads `API_BASE_URL`) | Hand-edit `index.html` per environment / fetch a runtime config endpoint | No bundler or npm dependency needed; single source of truth; keeps secrets out of the frontend; Pages build env var is the only manual step |
| 2026-10-20 | New lightweight CI job (`.github/workflows/ci.yml`, Python 3.11) runs `trader/tests` + `backend/tests` with mocked brokers | Reuse the upstream docker-based `test.yml` | Upstream workflow builds the full FinRL image; the V2 app needs its own gate that never needs credentials or network |
| 2026-10-20 | `finrl/config_private.py` untracked from the git index (kept on disk) | Leave it tracked | `.gitignore` already excludes it; tracking it defeats that intent and risks committing credentials |
| 2026-10-26 | Durable store moved to Neon PostgreSQL (pooled `-pooler` host, `sslmode=require`), Supabase retained read-only as rollback | Stay on Supabase direct/Session Pooler / migrate to another managed PG | Supabase direct host is IPv6-only and unreachable from Railway; Neon's pooler publishes A/AAAA. `DBStore`/`psycopg2` interface preserved; migration is additive, no data copied, source DB untouched |
| 2026-10-26 | Auto-apply `sslmode=require` for non-local DB hosts, with bounded connect timeout/retries and `application_name` | Require operators to hand-edit every DSN / no timeouts | Fail closed on unencrypted remote connections while keeping local development simple; bounded attempts prevent a hung deploy |
| 2026-10-26 | Dashboard stays vanilla ES2020 + hand-written SVG; no React/Vite | React + chart library | Preserves zero-build static hosting on Cloudflare Pages and keeps the bundle dependency-free; charts are small and accessible |
| 2026-10-26 | Dashboard password is held in memory only (never `sessionStorage`/URL); cancel password moved from query string to POST body | Persist password for convenience / keep query parameter | Avoid credential leakage through XSS persistence, proxy logs and browser history; read-only views stay usable without unlock |
| 2026-10-26 | Missing backend data renders as `null` + `available:false` (e.g. equity), not a fabricated `10000.0` | Keep a demo fallback balance | Never show invented portfolio state; zero and unknown must be distinguishable |
| 2026-10-26 | Test suite blanks every Alpaca alias and forces `DATA_PROVIDER=alpaca`; broker/market failures are monkeypatched where the unavailable path is asserted | Rely on missing credentials alone | Alpaca crypto data is readable without credentials and a developer `.env` can leak keys into tests; assertions must be deterministic and offline |
| 2026-10-26 | Execution outcome takes precedence over persistence: unknown status trips the kill switch before any DB I/O; persistence errors are returned as `persistence_error` | Persist first, treat DB failure as request failure | A storage blip must never hide an ambiguous order or skip fail-closed reconciliation; the broker, not the DB, is authoritative for execution |
| 2026-10-26 | `TRUST_PROXY_HEADERS` defaults to false; X-Forwarded-For is honored only when explicitly enabled (right-most hop) | Trust the header unconditionally / trust the left-most hop | A client-controlled header must not grant a fresh password-rate-limit bucket; Railway opts in because its edge appends the real address |
| 2026-10-26 | `/api/v2/health` actively probes PostgreSQL (5 s cached) when configured | Keep using query-free `stats()` | A dropped idle connection otherwise reports green until the next write, which is exactly how a deploy can look healthy while orders fail |
| 2026-10-26 | Remote PostgreSQL refuses `sslmode=disable/allow/prefer`; managed hosts default to `require` | Pass any operator-supplied sslmode through | TLS is mandatory for Neon/Supabase; fail closed instead of silently sending credentials in plaintext |
| 2026-10-26 | Cloudflare build pins CSP `connect-src` to `API_BASE_URL`'s origin | Keep `https:` wildcard | The bundle only needs one API origin; narrow CSP limits exfiltration if a dependency or injection appears |

| 2026-10-26 | Readiness = valid config AND (required durable store available); kill switch stays HTTP 200 | Return 503 for any `ok=false`, including `risk_killed` | A restarting orchestrator would otherwise clear the in-memory kill switch. `ok` still reports the kill switch in the body |
| 2026-10-26 | `stats().backend` names the configured store (`postgres` whenever DATABASE_URL is set); connection state is separate (`connected`/`durable`/`fallback_memory`) | Keep deriving `backend` from the live handle | A dropped idle connection was reported as "memory" even though `require_durable` refuses writes instead of buffering them |
| 2026-10-26 | Orders are refused (HTTP 503) before submission when the required durable store is unavailable; a submitted-but-unrecorded order trips the kill switch | Submit first, report the persistence error afterwards | An unrecorded live paper order is untracked risk; the execution path must fail closed before the broker is contacted |
| 2026-10-26 | alpaca-py calls get an injected per-request socket timeout (10 s read / 30 s submit) and a per-thread memoized client | Rely on `Future.result(timeout=...)` only / build a client per call | An abandoned future cannot stop a blocked socket; four hung reads made the account permanently unreadable. Reusing the client keeps TLS warm (1.9 s -> 0.27 s) |
| 2026-10-26 | Every state-changing route requires the dashboard credential, including the previously open compute routes (`/api/pipeline/run`, `/api/backtest`, `/api/walkforward`); `authed()` accepts the body field or the `X-Dashboard-Password` header, never a query string | Leave compute routes open / rate-limit only | `/api/backtest` persisted a row and all three were unauthenticated on a public URL; fail-closed (403 when no password is configured) is the existing contract for mutations |
| 2026-10-26 | Read gating when `DASHBOARD_PASSWORD` is set: portfolio, positions, orders, logs, signals, performance and job detail require the credential; health, market data, config and sanitized `/api/v2/db` stay public | Keep all reads public / require auth for every route | Those endpoints expose account information to anyone with the URL. Public health is required by the platform probe and public market data carries no account state. Installs without a password keep the previous open-read behaviour so local development is unchanged |
| 2026-10-26 | Broker health comes from a read-only `Broker.probe()` executed on a daemon thread (3 s first wait, 15 s result TTL), not a synchronous call in the request handler | Call Alpaca synchronously inside `/api/health` | A hung Alpaca call would otherwise delay (and eventually fail) the platform health check, causing a restart loop; the bounded wait returns `probing` instead |
| 2026-10-26 | Broker and Redis outages degrade `ok`/`status` but never `ready` (HTTP 503 stays reserved for invalid config or the required durable store) | Return 503 for any degraded dependency | A recoverable dependency outage must not restart the process (a restart also clears the in-memory kill switch); readiness and overall health are separate fields |
| 2026-10-26 | Redis availability is proven with a `PING` (2 s socket timeout) plus one rate-limited reconnect, and the payload reports `backend`/`fallback`/`latency_ms` | Infer availability from `stats()` (`INFO memory`) | INFO is not a connectivity check; a configured-but-down Redis must be labelled as an in-process cache fallback, not as healthy Redis |
| 2026-10-26 | `/docs`, `/redoc` and `/openapi.json` are off unless `ENABLE_API_DOCS=true` | Leave FastAPI defaults | A public deployment should not advertise its endpoint schema; an operator can opt in for debugging |
| 2026-10-26 | Client-facing error text goes through `public_error()`/`public_text()`, which redact IPv4 literals and `host=` values on top of `safe_msg()` | Return `safe_msg()` everywhere | Credentials were already redacted but host topology was not, and `/api/v2/db` is publicly readable |
